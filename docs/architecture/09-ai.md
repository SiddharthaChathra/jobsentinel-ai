# 09 — AI Architecture (`packages/ai`)

## 1. Principles

1. **Provider-independent.** One `AIProvider` interface; `GeminiAdapter`, `ClaudeAdapter`, `LocalModelAdapter` (OpenAI-compatible chat endpoint, e.g. Ollama). Chosen by `AI_PROVIDER`; fallback order `AI_FALLBACK_PROVIDERS` (e.g. `gemini,claude`).
2. **Structured output only.** Every call has a Zod output schema. Providers are asked for JSON (Gemini `responseMimeType: application/json` + `responseSchema`; Claude tool-use with an input schema; local: JSON mode when available). Output is parsed → repaired (strip fences, trailing commas) → Zod-validated → on failure one retry with the validation error appended → then `INVALID_JSON` and the deterministic fallback.
3. **AI is a signal, not a judge.** Every AI purpose has a defined deterministic fallback and a capped influence (doc 08 §3.6, §4 below).
4. **Minimum data.** Resume: only the extracted text (no file, no email/phone — PII is regex-redacted before sending, keeping name for the profile's display). Jobs: title, company, trimmed description, requirements. Never the user's email, tokens, or full history. Prompts set "do not retain" instructions where the provider offers a no-training API tier (Gemini API paid/free tiers differ in data-use terms — documented in doc 11; user can pick Claude or local if preferred).
5. **Budgeted & cached.** `ai_calls` records every call; `input_hash = sha256(purpose|prompt_version|normalized input)` makes repeat calls free; `AI_DAILY_CALL_BUDGET` (default 500) and `AI_DAILY_TOKEN_BUDGET` stop calls when exhausted (`BUDGET_EXCEEDED` → `AI_PENDING`).
6. **Versioned prompts.** `prompts/<purpose>.v<N>.ts`; version is stored on every result so a prompt change can trigger recomputation for open jobs only.

## 2. Interface

```ts
export interface AIRequest<T> {
  purpose: AIPurpose;                 // 'RESUME_PROFILE' | 'JOB_REQUIREMENTS' | 'FRESHER_CLASSIFY' | 'MATCH' | 'SUSPICION'
  promptVersion: string;
  system: string;
  user: string;
  schema: z.ZodType<T>;
  maxOutputTokens: number;
  temperature?: number;               // default 0.1
  cacheKeyInput: unknown;             // hashed for ai_calls.input_hash
  meta?: { jobId?: string; userId?: string };
}
export interface AIResult<T> =
  | { status: 'OK'; data: T; provider; model; usage: {input; output}; latencyMs; cached: boolean }
  | { status: 'INVALID_JSON' | 'ERROR' | 'BUDGET_EXCEEDED' | 'UNAVAILABLE'; error: string; provider? };

export interface AIProvider {
  readonly name: string; readonly model: string;
  complete(req: { system; user; jsonSchema; maxOutputTokens; temperature }): Promise<{ text: string; usage }>;
  healthCheck(): Promise<boolean>;
}

export class AIService {
  constructor(providers: AIProvider[], budget: BudgetPort, cache: CachePort, logger) {}
  run<T>(req: AIRequest<T>): Promise<AIResult<T>>;   // cache → budget → provider chain → parse → validate → record
}
```

Adapters:

| Adapter             | SDK                                                | Default model (config)                 | Notes                                                                |
| ------------------- | -------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| `GeminiAdapter`     | `@google/genai`                                    | `gemini-2.5-flash` (`AI_GEMINI_MODEL`) | free tier; native JSON schema                                        |
| `ClaudeAdapter`     | `@anthropic-ai/sdk`                                | `claude-haiku-4-5` (`AI_CLAUDE_MODEL`) | paid; tool-use for strict JSON; used when key present or as fallback |
| `LocalModelAdapter` | `fetch` to `AI_LOCAL_BASE_URL/v1/chat/completions` | any (`AI_LOCAL_MODEL`)                 | Ollama/LM Studio; MVP: interface + smoke test only                   |

Model names are config, never code constants — swapping models is an env change.

## 3. Purposes, prompts, schemas, fallbacks

| Purpose            | When                                                                      | Input (trimmed)                                                               | Output schema                                                                                                                                                                                                                     | Deterministic fallback if AI unavailable                                                                        |
| ------------------ | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `RESUME_PROFILE`   | on upload/analyze                                                         | redacted resume text ≤ 12 k chars                                             | `ResumeProfileDraft {name?, summary, education[], skills[{name, category, evidence}], projects[], experience[], certifications[], graduationYear?, experienceLevel, suggestedRoles[{title, tier, reason}], suggestedLocations[]}` | dictionary skill extraction + regex year/degree; roles left empty for user to pick — onboarding still completes |
| `JOB_REQUIREMENTS` | once per job before matching (cached by content_hash)                     | title, description ≤ 6 k, requirements                                        | `JobRequirements {mustHaveSkills[], niceToHaveSkills[], minYears?, maxYears?, educationRequired?, roleFamily, isFresherFriendly: 'YES'\|'NO'\|'UNCLEAR', reasons[]}`                                                              | dictionary skills + regex experience; roleFamily from title taxonomy                                            |
| `FRESHER_CLASSIFY` | only when rules say UNKNOWN/conflicting                                   | title, experience text, first 3 k chars                                       | `{level: ExperienceLevel, fresherEligible: boolean, confidence, evidence[]}`                                                                                                                                                      | rule result stands (UNKNOWN → included if `include_unknown_experience`, shown with "experience unclear" badge)  |
| `MATCH`            | per (job, profile_version) for VALID/NEEDS_REVIEW jobs passing pre-filter | profile skills/roles/locations/grad year + `JobRequirements` (not the raw JD) | `{skillScore, roleScore, experienceScore, locationScore, matchedSkills[], missingSkills[], explanation}`                                                                                                                          | deterministic scorer (§5) — always computed anyway; AI refines skill/role semantics                             |
| `SUSPICION`        | ambiguous validation (doc 08)                                             | title, company, ≤ 3 k description, found flags, URL relationship              | `{verdict, confidence, reasons[]}`                                                                                                                                                                                                | no AI contribution (0)                                                                                          |

Prompts are terse, instruct "answer only from the provided text, never invent", and include 2–3 few-shot examples for Indian fresher listings (e.g. "0–1 years", "2026/2027 batch", "B.E./B.Tech freshers").

## 4. Fresher / eligibility decision (rules + AI, never keywords alone)

```
rulesResult = classifyExperience(title, experienceText, description)   // packages/validation
  positive indicators: fresher, fresh graduate, graduate engineer, entry level, new grad, campus, early career,
                       trainee, 0 years, 0-1, 0-2, "2026 batch", "recent graduates", intern → (INTERNSHIP type)
  negative indicators: senior, staff, lead, principal, manager, architect, head, director, "3+ years", "minimum 2 years", "5-8 yrs"
  parsed years: (min,max)

  if negative title token or min >= 3           → EXPERIENCED (conf 0.9)
  elif max <= 1 or positive token & min == 0    → FRESHER (0.85)
  elif min <= 1 and max <= 3                    → ENTRY_LEVEL (0.7)
  elif no signals                               → UNKNOWN
  elif conflicting                              → UNKNOWN (flag CONFLICT)
if rulesResult ∈ {UNKNOWN} or confidence < 0.6 → FRESHER_CLASSIFY (AI)   [budget permitting]
final.fresherEligible = level ∈ {FRESHER, ENTRY_LEVEL}; evidence = rules evidence ∪ AI evidence
```

`fresher_only` preference hides EXPERIENCED; UNKNOWN is kept with a visible badge (spec: never solely keyword-based, never silently drop).

## 5. Matching & priority

Deterministic scorer (always runs, unit-tested):

```
skillScore      = 100 · weightedOverlap(profile.skills, req.mustHave ×1.0 ∪ req.niceToHave ×0.4)  using skill aliases
roleScore       = 100 if role_family ∈ PRIMARY roles; 80 SECONDARY; 60 OTHER selected; 30 same category; 10 otherwise
experienceScore = 100 FRESHER, 85 ENTRY_LEVEL, 50 UNKNOWN, 0 EXPERIENCED (10 if fresher_only=false)
locationScore   = 100 remote ok / preferred city; 75 preferred country; 40 other; 100 if prefs = ANY
overall         = round(0.40·skill + 0.30·role + 0.20·experience + 0.10·location)
```

AI (`MATCH`) replaces `skillScore` and `roleScore` when available (semantic matching, e.g. "REST APIs" ≈ "backend development"), bounded to ±25 of the deterministic value to prevent hallucinated jumps; `explanation` always lists concrete matched/missing skills.

Priority bands: 90–100 VERY_HIGH, 75–89 HIGH, 60–74 MEDIUM, < 60 OTHER. Bands organize and gate _notifications_ only; nothing is deleted because of a score.

Pre-filter before spending AI on `MATCH`: category monitored ∧ fresher not EXPERIENCED (unless allowed) ∧ deterministic overall ≥ 35. Below that, the deterministic score is stored and the job is still visible under "Other Opportunities".

## 6. Budget & cost model (free tier)

| Workload (personal)                     | Calls/day (est.)                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------------- |
| New jobs after filters                  | ~50–150                                                                                      |
| `JOB_REQUIREMENTS` (cached per content) | ≤ 150                                                                                        |
| `MATCH`                                 | ≤ 150                                                                                        |
| `FRESHER_CLASSIFY` (ambiguous only)     | ≤ 40                                                                                         |
| `SUSPICION`                             | ≤ 20                                                                                         |
| Resume analysis                         | ~1                                                                                           |
| **Total**                               | **≤ ~400/day**, ~1 k tokens avg → within Gemini free-tier request limits; budget env caps it |

When exhausted, jobs wait in `AI_PENDING`; deterministic scores/validations are already stored, so the dashboard still works and instant alerts use the deterministic score if `AI_ALLOW_DETERMINISTIC_ALERTS=true` (default true).

## 7. Testing the AI layer

- Adapters: contract tests with recorded responses (no live calls in CI); one optional live smoke test behind `AI_LIVE_TESTS=1`.
- `AIService`: invalid JSON → repair → retry → fallback; budget exhaustion; provider chain failover; cache hit.
- Prompt regression fixtures: 30 real-style job descriptions with expected `FRESHER_CLASSIFY`/`JOB_REQUIREMENTS` outputs, run live manually before changing a prompt version.
