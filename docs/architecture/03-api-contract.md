# 03 — API Contract (REST, `/api/v1`)

## 1. Conventions

- Base path `/api/v1`. JSON only. All timestamps ISO-8601 UTC.
- **Auth:** `Authorization: Bearer <Supabase access token>` on every route except `/health*` and `POST /auth/signup-check`. The API verifies the JWT signature against the project JWKS and loads/creates the `users` row.
- **Envelope:**
  ```json
  { "data": …, "meta": { "nextCursor": "…", "total": 123 } }
  { "error": { "code": "JOB_NOT_FOUND", "message": "…", "details": {…}, "requestId": "…" } }
  ```
- **Pagination:** cursor-based (`?cursor=&limit=` default 20, max 100). Cursor is an opaque base64 of `(sortValue, id)`.
- **Validation:** every body/query is parsed with a Zod schema from `packages/types` (`ZodValidationPipe`). Invalid → `400 VALIDATION_ERROR` with field paths.
- **Errors:** `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 *_NOT_FOUND`, `409 CONFLICT`, `413 FILE_TOO_LARGE`, `415 UNSUPPORTED_FILE_TYPE`, `422 UNPROCESSABLE`, `429 RATE_LIMITED`, `503 AI_UNAVAILABLE`.
- **Rate limits:** 120 req/min per user, 10/min for `POST /resumes` and `POST /sources/:id/scan`.
- **Idempotency:** save/unsave/apply endpoints are idempotent (repeat → same state, 200).
- OpenAPI document generated by `@nestjs/swagger` at `/api/docs` (disabled in production unless `ENABLE_API_DOCS=true`).

## 2. Endpoints

### Sign-up pre-check (no auth)

| Method | Path                 | Body                             | Response                                     |
| ------ | -------------------- | -------------------------------- | -------------------------------------------- |
| POST   | `/auth/signup-check` | `{ email }` (`SignupCheckInput`) | `{ allowed: boolean }` (`SignupCheckResult`) |

Answers whether `ALLOWED_SIGNUP_EMAILS` admits an email, so the sign-up page can refuse before Supabase creates an account. Throttled to 10/min per client (the global limit is `RATE_LIMIT_PER_MIN`). The allow-list is still enforced on every authenticated request; this route only improves the refusal (D91).

`JobsQuery`:

```ts
{
  q?: string;                 // full-text (title + description)
  roleFamily?: string[];
  category?: JobCategory[];
  companyId?: string;
  location?: string;          // matches city/country/text
  remote?: boolean;
  fresherOnly?: boolean;      // default true
  experienceLevel?: ExperienceLevel[];
  minScore?: number;          // 0-100
  priority?: PriorityBand[];
  validationStatus?: ValidationStatus[];   // default ['VALID']; user may add NEEDS_REVIEW
  status?: 'ACTIVE' | 'EXPIRED' | 'ALL';   // default ACTIVE
  postedAfter?: string;       // ISO
  sourceId?: string;
  salaryMin?: number;
  saved?: boolean;
  tracker?: ApplicationStatus[];
  sort?: 'newest' | 'score' | 'posted' ;   // default newest
  cursor?: string; limit?: number;
}
```

`JobCard` (list item):

```ts
{
  id, title, company: { id, name, domain, verificationStatus },
  location: { text, city, country, isRemote },
  employmentType, experienceLevel, fresherEligible, experienceText,
  salary: { min, max, currency, period, text } | null,
  postedAt, firstSeenAt, deadline,
  validation: { status, confidence, companyVerified, applicationVerified, jobActive },
  match: { overallScore, priority, matchedSkills: string[] } | null,
  tracker: { saved: boolean, status: ApplicationStatus | null },
  applicationUrl,           // final_application_url ?? application_url
  isNew: boolean            // first_seen_at within 24h and not viewed
}
```

`JobDetail` = `JobCard` + `description`, `requirements[]`, `skills[]`, `sourceUrl`, `sources: [{name, url, firstSeenAt}]`, `validationDetail` (url check, evidence list, suspicious flags, AI assessment), `match.explanation`, `match.skillScore/roleScore/experienceScore/locationScore`, `match.missingSkills`, `events[]` (last 10).

## 3. Shared DTO schemas (in `packages/types/src/api/*.ts`)

Every request/response type above is a Zod schema exported from `packages/types`, e.g.:

```ts
export const PreferencesInput = z.object({
  locations: z.array(z.string().min(1)).max(20),
  remotePreference: RemotePreference,
  employmentTypes: z.array(EmploymentType).min(1),
  categories: z.array(JobCategory).min(1),
  fresherOnly: z.boolean(),
  includeUnknownExperience: z.boolean(),
  salaryMin: z.number().int().positive().nullable(),
  salaryCurrency: z.string().length(3),
  graduationYear: z.number().int().min(2000).max(2035).nullable(),
  timezone: z.string(),
  instantMinScore: z.number().int().min(0).max(100),
});
export type PreferencesInput = z.infer<typeof PreferencesInput>;
```

Gemini's frontend imports these types directly, so the UI and API cannot drift. The `apps/web/lib/api.ts` client is a thin typed fetch wrapper generated by hand from these schemas (no codegen step in MVP).

## 5. Versioning & compatibility rules

- Additive changes only within `v1`; breaking changes go to `/api/v2`.
- Every enum returned to the frontend is a string; unknown enum values must be tolerated by the UI (render as "Other").
- The API never returns `extracted_text` of resumes unless explicitly requested by the owner, and never returns raw source payloads to non-admins.
