# 03 — API Contract (REST, `/api/v1`)

## 1. Conventions

- Base path `/api/v1`. JSON only. All timestamps ISO-8601 UTC.
- **Auth:** `Authorization: Bearer <Supabase access token>` on every route except `/health*` and `POST /auth/signup-check`. The API verifies the JWT signature against the project JWKS and loads/creates the `users` row.
- **Envelope:**
  ```json
  { "data": …, "meta": { "nextCursor": "…", "total": 123 } }
  { "error": { "code": "JOB_NOT_FOUND", "message": "…", "details": {…}, "requestId": "…" } }
  ```
- **Pagination:** cursor-based (`?cursor=&limit=` default 20, max 100). Cursor is an opaque base64 of `(sortValue, id)`.
- **Validation:** every body/query is parsed with a Zod schema from `packages/types` (`ZodValidationPipe`). Invalid → `400 VALIDATION_ERROR` with field paths.
- **Errors:** `401 UNAUTHENTICATED`, `403 FORBIDDEN`, `404 *_NOT_FOUND`, `409 CONFLICT`, `413 FILE_TOO_LARGE`, `415 UNSUPPORTED_FILE_TYPE`, `422 UNPROCESSABLE`, `429 RATE_LIMITED`, `503 AI_UNAVAILABLE`.
- **Rate limits:** 120 req/min per user, 10/min for `POST /resumes` and `POST /sources/:id/scan`.
- **Idempotency:** save/unsave/apply endpoints are idempotent (repeat → same state, 200).
- OpenAPI document generated by `@nestjs/swagger` at `/api/docs` (disabled in production unless `ENABLE_API_DOCS=true`).

## 2. Endpoints

### Sign-up pre-check (no auth)

| Method | Path                 | Body                             | Response                                     |
| ------ | -------------------- | -------------------------------- | -------------------------------------------- |
| POST   | `/auth/signup-check` | `{ email }` (`SignupCheckInput`) | `{ allowed: boolean }` (`SignupCheckResult`) |

Answers whether `ALLOWED_SIGNUP_EMAILS` admits an email, so the sign-up page can refuse before Supabase creates an account. Throttled to 10/min per client (the global limit is `RATE_LIMIT_PER_MIN`). The allow-list is still enforced on every authenticated request; this route only improves the refusal (D91).

`JobsQuery`:

```ts
{
  q?: string;                 // full-text (title + description)
  roleFamily?: string[];
  category?: JobCategory[];
  companyId?: string;
  location?: string;          // matches city/country/text
  remote?: boolean;
  fresherOnly?: boolean;      // default true
  experienceLevel?: ExperienceLevel[];
  minScore?: number;          // 0-100
  priority?: PriorityBand[];
  validationStatus?: ValidationStatus[];   // default ['VALID']; user may add NEEDS_REVIEW
  status?: 'ACTIVE' | 'EXPIRED' | 'ALL';   // default ACTIVE
  postedAfter?: string;       // ISO
  sourceId?: string;
  salaryMin?: number;
  includeUndisclosedSalary?: boolean;     // default true: with salaryMin, keep "Not disclosed" jobs (D111)
  postingType?: ('CAMPUS_DRIVE' | 'OFF_CAMPUS_PROGRAM' | 'REGULAR')[];   // D114
  saved?: boolean;
  tracker?: ApplicationStatus[];
  sort?: 'newest' | 'score' | 'posted' ;   // default newest
  cursor?: string; limit?: number;
}
```

`JobCard` (list item):

```ts
{
  id, title, company: { id, name, domain, verificationStatus },
  location: { text, city, country, isRemote },
  employmentType, experienceLevel, fresherEligible, experienceText,
  salary: { min, max, currency, period, text } | null,
  postedAt, firstSeenAt, deadline,
  validation: { status, confidence, companyVerified, applicationVerified, jobActive },
  match: { overallScore, priority, matchedSkills: string[] } | null,
  tracker: { saved: boolean, status: ApplicationStatus | null },
  applicationUrl,           // final_application_url ?? application_url
  isNew: boolean            // first_seen_at within 24h and not viewed
}
```

`JobDetail` = `JobCard` + `description`, `requirements[]`, `skills[]`, `sourceUrl`, `sources: [{name, url, firstSeenAt}]`, `validationDetail` (url check, evidence list, suspicious flags, AI assessment), `match.explanation`, `match.skillScore/roleScore/experienceScore/locationScore`, `match.missingSkills`, `events[]` (last 10).

**Needs review (C step 2, D106).** `GET /jobs/needs-review` lists jobs with `status = NEEDS_REVIEW` — held by classification (category or experience unknown, D105, D110; such a job is validated too and keeps its hold) or by verification (company not verified, page unreachable, …) — with the same filters and gates as `/jobs`: the user's places, India-or-remote and batch (applied at classification), "0 to any" experience, the 60-day window and open jobs. Suspected scams (`SUSPICIOUS`) are excluded. `held.kind` ∈ `CATEGORY_UNKNOWN | EXPERIENCE_UNKNOWN | COMPANY_UNVERIFIED | URL_UNREACHABLE | OTHER` (a client must handle a kind it does not know as `OTHER`); `held.label` is the sentence to show. These jobs are never in `/jobs` and never sent to Telegram. Samples: `docs/contracts/needs-review.mock.json` (captured from the real API).

**Card fields added in Phase 13 (all optional for older clients).** `postingType` (D114); `attribution: { provider: 'ADZUNA', label: 'Adzuna', url } | null` — when present, the card and the detail page must show `label` as a link to `url`, at least 116 × 23 px (Adzuna's terms, D115); `match.scoring: 'RULES_ONLY' | 'AI_REFINED'` (D112). `SystemStatus.ai.userCallLimit` is the per-user daily AI limit. `SourceReportRow.placeholdersSkipped` and `totals.placeholdersSkipped` count talent-pool / general-application postings, which are never in `collected` or `kept` (D117). `company.hiresFreshersOften: boolean` is true when the company's fresher score is HIGH (F4, D118) — a badge only, never a filter or a sort. `NotificationSettings` adds `remindersEnabled` (default true), `followUpDays` (3-14, default 7) and `weeklySummaryEnabled` (default false, F6); `InboxItem.type` can be `REMINDER` or `WEEKLY`; a `WEEKLY` item's `title` is "Weekly summary — <dates>" and its `body` is the plain-text summary (F6, D121).

### Saved & applications (tracker)

| Method | Path                         | Body                                                                              | Response                                          |
| ------ | ---------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------- |
| GET    | `/saved-jobs`                | cursor                                                                            | `JobCard[]`                                       |
| GET    | `/applications?status=`      | —                                                                                 | `ApplicationItem[]` (job card + status + history) |
| PUT    | `/applications/:jobId`       | `{ status: ApplicationStatus, notes?, appliedAt? }`                               | `ApplicationItem`                                 |
| DELETE | `/applications/:jobId`       | —                                                                                 | 204 (removes from tracker)                        |
| PATCH  | `/applications/:jobId/dates` | `ApplicationDatesInput`: `{ deadline?, interviewAt?, followUpAt? }` (ISO or null) | `ApplicationItem` (creates a VIEWED row if none)  |

**Tracker reminders (F5, D119).** `ApplicationItem` adds `deadline` (the user's, else the posting's), `interviewAt`, `followUpAt` (the override, else last status change + `followUpDays`) and `lastStatusChangeAt` — all optional for older clients.

| Method | Path                      | Body                              | Response                                                            |
| ------ | ------------------------- | --------------------------------- | ------------------------------------------------------------------- |
| GET    | `/reminders?withinDays=7` | —                                 | `ReminderItem[]`: DUE (sent or overdue, not dismissed) and UPCOMING |
| POST   | `/reminders/:id/snooze`   | `{ hours?: 1..168 }` (default 24) | `ReminderItem` (PENDING again; re-delivered then)                   |
| POST   | `/reminders/:id/dismiss`  | —                                 | 204                                                                 |

Rules: FOLLOW_UP when APPLIED with no status change for `followUpDays` (3-14, default 7), once per stretch; INTERVIEW_DAY_BEFORE and INTERVIEW_MORNING (08:00 local, 07:00 for an interview before 09:00); DEADLINE_3D and DEADLINE_1D for saved, not-applied jobs. INTERVIEW cancels the follow-up and deadline reminders; REJECTED / SELECTED / NOT_INTERESTED cancel everything. Never sent 22:00-07:00 in the user's timezone or in their own quiet hours: deferred, not dropped. Delivered as `REMINDER` notifications (inbox + Telegram). Samples: `docs/contracts/reminders.mock.json` (checked by `packages/types/src/contracts.test.ts`).

### Skill gaps (F7, D120)

### Sources (admin)

| Method | Path                         | Body                                                                                                     | Response                                                                                                            |
| ------ | ---------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET    | `/sources`                   | —                                                                                                        | `SourceSummary[]` (status, last scan, failures, next scan)                                                          |
| POST   | `/sources`                   | `SourceInput` (adapter, config, priority, companyId?) — config validated by the adapter's own Zod schema | `Source` 201                                                                                                        |

| GET    | `/sources/report?days=7\|30` | — (default 30)                                                                                           | `SourceReport` — per source: collected, kept, `rejected` by reason, `health`, `lastKeptAt`, pause fields (F2, D103) |
| POST   | `/sources/:id/resume`        | —                                                                                                        | 200 `{ id, status: 'ACTIVE' }`; 409 `SOURCE_NOT_PAUSED`; 404 `SOURCE_NOT_FOUND`                                     |
| GET    | `/sources/:id/scan-runs`     | cursor                                                                                                   | `ScanRun[]`                                                                                                         |
| GET    | `/companies?q=`              | —                                                                                                        | `Company[]`                                                                                                         |
| PATCH  | `/companies/:id`             | `{ isTrusted?, isBlocked?, websiteDomain?, careersUrl? }`                                                | `Company`                                                                                                           |

**Source report card (F2, D103).** _Collected_ = jobs a source first saw inside the window; _kept_ = those that passed every gate (India or remote, fresher "0 to any", validated, open, inside 60 days). `rejected` counts the first gate each other job failed: `LOCATION`, `EXPERIENCE`, `BATCH`, `CATEGORY`, `VALIDATION`, `EXPIRED`, `STALE`, `OTHER`; `PENDING` is still in the pipeline, not a rejection. `health` keeps three cases apart: `ERRORS` (failing — the scan backoff handles it), `COLLECTED_NOTHING` (possibly broken — look at it) and `KEPT_ZERO` (collects, nothing fits — the auto-pause candidate); plus `OK` and `PAUSED`. `pauseExempt: true` marks an India-scoped source: never auto-paused, alerted on instead (D104). Sample responses for every case, including errors: `docs/contracts/source-report.mock.json` (checked against the schemas by `packages/types/src/contracts.test.ts`).

## 3. Shared DTO schemas (in `packages/types/src/api/*.ts`)

Every request/response type above is a Zod schema exported from `packages/types`, e.g.:

```ts
export const PreferencesInput = z.object({
  locations: z.array(z.string().min(1)).max(20),
  remotePreference: RemotePreference,
  employmentTypes: z.array(EmploymentType).min(1),
  categories: z.array(JobCategory).min(1),
  fresherOnly: z.boolean(),
  includeUnknownExperience: z.boolean(),
  salaryMin: z.number().int().positive().nullable(),
  salaryCurrency: z.string().length(3),
  graduationYear: z.number().int().min(2000).max(2035).nullable(),
  timezone: z.string(),
  instantMinScore: z.number().int().min(0).max(100),
});
export type PreferencesInput = z.infer<typeof PreferencesInput>;
```

Gemini's frontend imports these types directly, so the UI and API cannot drift. The `apps/web/lib/api.ts` client is a thin typed fetch wrapper generated by hand from these schemas (no codegen step in MVP).

## 5. Versioning & compatibility rules

- Additive changes only within `v1`; breaking changes go to `/api/v2`.
- Every enum returned to the frontend is a string; unknown enum values must be tolerated by the UI (render as "Other").
- The API never returns `extracted_text` of resumes unless explicitly requested by the owner, and never returns raw source payloads to non-admins.
